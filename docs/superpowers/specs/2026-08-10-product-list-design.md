# 상품 목록 및 린트 정상화 설계

## 목표

- 루트 프론트엔드 린트가 별도 Git 저장소인 `backend/`를 검사하지 않게 한다.
- 중고마켓 상품 목록에 검색, 베스트 상품, 페이지네이션, 빈 상태를 추가한다.
- 검색·정렬·페이지 상태를 URL 쿼리에 보존한다.

## 범위

### 린트

- 루트 ESLint 전역 제외 목록에 `backend/**`를 추가한다.
- 프론트엔드 `src/`의 기존 린트 규칙은 변경하지 않는다.
- 중첩 저장소인 `backend/` 자체 코드는 수정하지 않는다.

### 상품 목록

- 페이지 상단에 좋아요순 상품 4개를 베스트 상품으로 표시한다.
- 베스트 상품은 검색어, 전체 상품 정렬, 현재 페이지와 독립적으로 조회한다.
- 모바일에서는 2열, 태블릿 이상에서는 4열로 표시한다.
- 전체 상품은 페이지당 10개를 조회한다.
- 검색은 입력만으로 실행하지 않고 검색 버튼이나 Enter 제출로 실행한다.
- 정렬은 최신순과 좋아요순을 지원한다.
- 검색 또는 정렬 변경 시 페이지를 1로 초기화한다.
- 페이지네이션은 이전, 최대 5개의 페이지 번호, 다음 버튼으로 구성한다.
- `page`가 양의 정수가 아니면 1로 보정한다.
- 검색 결과가 없으면 검색어를 포함한 빈 상태 문구를 표시한다.

## 상태와 URL

목록 상태의 기준은 URL 쿼리다.

- `keyword`: 제출된 검색어. 공백을 제거한 뒤 빈 값이면 쿼리에서 생략한다.
- `orderBy`: `recent` 또는 `favorite`. 유효하지 않으면 `recent`를 사용한다.
- `page`: 1 이상의 정수. 유효하지 않으면 1을 사용하며 1은 쿼리에서 생략할 수 있다.

검색 입력값은 제출 전까지 로컬 상태로 유지한다. 제출, 정렬 변경, 페이지 이동은 기존 조건을 보존해 URL을 갱신한다.

## 데이터 흐름

`ItemsPage`는 URL에서 목록 조건을 읽고 두 요청을 독립적으로 수행한다.

1. 베스트 상품: `getProducts({ page: 1, pageSize: 4, orderBy: "favorite" })`
2. 전체 상품: `getProducts({ page, pageSize: 10, keyword, orderBy })`

전체 상품 응답의 `totalCount`로 전체 페이지 수를 계산한다. 조건 변경으로 새 요청이 시작되면 이전 요청의 결과가 최신 상태를 덮지 않도록 effect 정리 상태를 확인한다.

## 오류와 빈 상태

- 베스트 상품 조회 실패는 베스트 영역 안에서만 안내하고 전체 목록은 계속 사용할 수 있게 한다.
- 전체 상품 조회 실패는 전체 목록 영역에 재시도 가능한 의미의 오류 문구를 표시한다.
- 전체 상품 결과가 비어 있으면 검색어가 있을 때는 해당 검색 결과가 없음을, 없을 때는 등록된 상품이 없음을 표시한다.
- 로딩 상태도 두 영역에서 독립적으로 표시한다.

## 테스트

구현 전에 다음 동작을 실패하는 테스트로 고정한다.

- URL 쿼리에서 유효한 검색·정렬·페이지 조건을 읽는다.
- 잘못된 정렬과 페이지 값을 기본값으로 보정한다.
- 조건 변경용 URL을 만들 때 기존 조건을 보존하고 필요 없는 기본값을 생략한다.
- `totalCount`와 페이지 크기로 전체 페이지 수를 계산한다.
- 현재 페이지를 기준으로 최대 5개의 연속된 페이지 번호를 만든다.

구현 후 단위 테스트, `npm run lint`, `npm run build`를 모두 실행한다.

## 제외 범위

- 상품 상세의 삭제, 좋아요, 판매자, 댓글 기능
- 로그인과 권한 처리
- 게시판 기능 변경
- `backend/` 저장소 내부 린트 오류 수정
