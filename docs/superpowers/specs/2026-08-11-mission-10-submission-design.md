# 스프린트 미션 10 제출 마무리 설계

## 목표

프론트엔드와 백엔드 저장소가 스프린트 미션 10의 TypeScript 요구사항을 충족하는지 검증하고, 멘토가 바로 리뷰할 수 있는 GitHub PR 상태로 정리한다.

## 범위

### 프론트엔드

- 현재 작업 브랜치 `feature/sprint-mission-next-pr`를 유지한다.
- 기준 브랜치와의 차이를 확인하고, 충돌 없이 필요한 최신 커밋만 반영한다.
- 기존 Draft PR #2의 제목과 본문을 미션 10 기준으로 갱신한다.
- 검증이 모두 통과한 뒤 PR을 Ready for review로 전환한다.

### 백엔드

- 기존 Express TypeScript 코드는 유지한다.
- 개발 명령을 요구사항에 맞게 `nodemon`이 `.ts` 변경을 감지하고 `ts-node`로 서버를 다시 실행하도록 구성한다.
- `ts-node`를 개발 의존성으로 추가하고, `package.json` 및 잠금 파일만 필요한 만큼 변경한다.
- 로컬 도구 폴더 `.omc/`는 백엔드 커밋에서 제외한다.
- 기존 개인 브랜치에서 변경을 커밋하고 사용자 포크에 push한 뒤 Draft PR을 생성한다.

## 검증

- 프론트엔드: `npm test`, `npm run lint`, `npm run build`
- 백엔드: 설정 계약 테스트, `npm test`, `npm run build`
- 정적 확인: `any` 사용, 인터페이스·타입 별칭·Union·Intersection·Generics·유틸리티 타입 사용 여부
- GitHub 확인: 로컬과 원격 커밋 일치, PR head/base, Draft 상태, 제목과 본문

## 오류 처리와 안전성

- 사용자 변경과 로컬 도구 파일은 명시적으로 스테이징 대상에서 제외한다.
- 기준 브랜치 반영 중 충돌이 발생하면 임의 해결하지 않고 실제 충돌 파일을 확인한다.
- 테스트나 빌드가 실패하면 PR을 Ready로 전환하지 않는다.
- PR 대상 브랜치가 불명확하면 기존 저장소의 기본 브랜치와 개인 브랜치 관계를 확인한 뒤 결정한다.

## 완료 기준

- 두 프로젝트의 TypeScript 컴파일과 테스트가 통과한다.
- 백엔드 개발 서버가 `nodemon + ts-node` 구성으로 실행된다.
- 프론트엔드와 백엔드 변경이 사용자 원격 저장소에 push된다.
- 두 PR이 미션 10 제목과 검증 결과를 포함하고 Ready for review 상태다.
