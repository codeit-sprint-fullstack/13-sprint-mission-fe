# 상품 상세 상호작용 및 권한 설계

## 목표

- 상품 상세에서 좋아요와 좋아요 취소를 실제 API에 연결한다.
- 상품 작성자가 자신의 상품을 수정하거나 삭제할 수 있게 한다.
- 상품 댓글을 조회, 등록, 수정, 삭제할 수 있게 한다.
- 로그인 여부와 작성자 권한에 따라 가능한 동작과 화면을 일관되게 제한한다.

## 범위

### 프론트엔드

- 인증 토큰을 포함해 상품 상세를 조회하고 `isLiked`를 화면에 반영한다.
- 상품 삭제, 좋아요, 댓글 CRUD API 함수를 추가한다.
- 상품 상세 화면에 좋아요 버튼, 작성자 전용 수정·삭제 버튼, 댓글 UI를 추가한다.
- 비로그인 사용자가 인증이 필요한 동작을 시도하면 `/login`으로 이동한다.
- 요청별 로딩과 오류 상태를 분리해 중복 요청과 화면 전체 실패를 방지한다.

### 백엔드 응답 계약

- 상품 상세 응답에 상품 작성자를 판별할 수 있는 `ownerId`를 포함한다.
- 상품 댓글 응답에 댓글 작성자를 판별할 수 있는 `writer.id`와 `writer.nickname`을 포함한다.
- 기존 인증 및 소유권 검사는 유지한다.
- 목록 응답은 이번 변경 범위에 포함하지 않는다.

## 데이터 모델

`Product`는 다음 선택 필드를 추가로 사용한다.

- `ownerId?: number`: 상품 작성자 사용자 ID
- `isLiked?: boolean`: 현재 로그인 사용자의 좋아요 여부

`Comment`는 기존 게시글 댓글과 상품 댓글에서 공통으로 사용하며 `writer?: Writer`를 통해 작성자를 식별한다.

백엔드는 상품 상세 직렬화 시 내부 `userId`를 `ownerId`로 노출한다. 상품 댓글 목록과 생성·수정 응답은 동일한 댓글 형태를 사용한다.

## API 인터페이스

`src/lib/products.ts`는 다음 함수를 제공한다.

- `deleteProduct(id): Promise<void>`
- `likeProduct(id): Promise<Product>`
- `unlikeProduct(id): Promise<Product>`
- `getProductComments(productId, options?): Promise<CursorListResponse<Comment>>`
- `createProductComment(productId, input): Promise<Comment>`
- `updateProductComment(productId, commentId, input): Promise<Comment>`
- `deleteProductComment(productId, commentId): Promise<void>`

상품 상세 조회와 모든 변경 요청은 저장된 액세스 토큰을 전송한다. 댓글 목록 조회는 공개 요청으로 유지한다.

## 화면 동작

### 상품과 권한

- 상품을 불러오는 동안 기존 로딩 화면을 표시한다.
- 상품 조회 실패 시 상품 목록으로 이동한다.
- 저장된 사용자 ID와 `product.ownerId`가 같을 때만 수정·삭제 버튼을 표시한다.
- 상품 삭제 전 확인 창을 표시하고 성공하면 `/items`로 이동한다.
- 삭제 실패는 상세 화면 안에 오류 문구로 표시한다.

### 좋아요

- 로그인 사용자는 좋아요 버튼으로 상태를 토글한다.
- 비로그인 사용자가 버튼을 누르면 `/login`으로 이동한다.
- 처리 중에는 버튼을 비활성화해 중복 요청을 막는다.
- 성공 응답의 `isLiked`와 `likeCount`를 사용해 화면을 갱신한다.
- 실패하면 기존 상태를 유지하고 좋아요 영역에 오류를 표시한다.

### 댓글

- 댓글 목록은 상품과 독립적으로 조회한다.
- 비로그인 사용자가 댓글 입력을 시작하거나 등록을 시도하면 `/login`으로 이동한다.
- 등록 성공 시 새 댓글을 목록에 추가하고 입력값을 비운다.
- 저장된 사용자 ID와 `comment.writer.id`가 같을 때만 댓글 수정·삭제 버튼을 표시한다.
- 수정 성공 시 해당 댓글을 교체하고, 삭제 성공 시 목록에서 제거한다.
- 등록 중 중복 제출을 막고 댓글 요청 오류는 댓글 영역에 표시한다.

## 오류 처리

- 상품, 삭제, 좋아요, 댓글 요청의 오류 상태를 서로 분리한다.
- 인증이 필요한 동작 전에 프론트에서 로그인 여부를 확인한다.
- 백엔드의 401·403 검사는 최종 권한 경계로 유지한다.
- 실패한 변경 요청은 성공한 것처럼 낙관적으로 반영하지 않는다.

## 테스트

- 인증된 상품 상세 요청이 `Authorization` 헤더를 전송하는지 검증한다.
- 삭제·좋아요·댓글 CRUD가 올바른 URL, HTTP 메서드, JSON 본문을 사용하는지 검증한다.
- 현재 사용자 ID와 리소스 작성자 ID의 일치 여부를 계산하는 순수 권한 함수를 검증한다.
- 백엔드 상품 상세가 `ownerId`를, 댓글 응답이 `writer`를 반환하는지 검증한다.
- 구현 후 프론트 단위 테스트, ESLint, TypeScript 검사, 프로덕션 빌드를 실행한다.
- 백엔드 TypeScript 검사와 빌드를 실행한다.

## 제외 범위

- 게시글 목록 페이지네이션과 베스트 게시글 개선
- 공통 API 클라이언트 전면 리팩터링
- 쿠키 기반 인증 또는 서버 세션 전환
- 댓글 무한 스크롤과 추가 페이지 로딩
- 상품 목록 카드에서의 좋아요 조작
